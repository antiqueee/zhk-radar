# Радар проблемных ЖК

Внутренний инструмент агентства: проверяемые сигналы по отдельным корпусам,
оценка приоритета и подготовка материалов для руководителей.
Требования сохранены без изменений в [docs/SPEC.md](docs/SPEC.md).

**Статус: начальная реализация, не действующий мониторинг.**
Создан отдельный локальный Git-репозиторий, ветка `feat/01-foundation`.
Удалённый репозиторий и серверы не подключены. Платных вызовов и отправок нет.

Реализовано:

- Python 3.12, uv и lock-файл; конфигурация окружения без боевых ключей.
- Начальная схема PostgreSQL: developers, complexes, objects, object_snapshots,
  sources, documents, signals, signal_documents, runs. Alembic и pg_trgm.
- Чистые функции R1–R7, три оси скоринга, классы, уверенность и стоп-лист.
- Проверка дословной цитаты и ключ дедупликации по неделе, уровню и сущности.
- Объяснение расчёта и явные ограничения при неполных входных данных.
- Воспроизводимый пример на синтетических данных, 34 офлайн-теста.
- Docker Compose для тестовой базы и мигратора; CI с PostgreSQL 16.

Ещё не реализованы: сборщики, сохранение сигналов через прикладной сервис,
весь недельный конвейер, шлюз моделей, читатель чатов, бот, Sheets, PDF,
планировщик и эксплуатационные резервные копии. Схема базы будет расширяться
следующими миграциями. CLI `demo` не записывает данные в БД.

## Локальный запуск

Из корня репозитория:

```sh
uv sync --frozen --python 3.12
uv run radar demo
uv run pytest -q
uv run ruff check .
uv run ruff format --check .
```

Ожидаемый пример: острота 73, продаваемость 65, окно 90, класс A,
уверенность высокая, правило R3. Это вымышленный объект, не результат исследования.
Можно передать собственный файл через `radar demo --input path.json`.
Формат — [tests/fixtures/scenario.json](tests/fixtures/scenario.json).
Дата расчёта передаётся явно, поэтому результат воспроизводим.

## Тестовая база

Нужен установленный и работающий Docker. На машине первой разработки его нет.

```sh
cp .env.example .env
chmod 600 .env
docker compose up -d db
uv run alembic upgrade head
uv run alembic check
```

Либо `docker compose --profile tools run --rm migrate` для миграции в контейнере.
Пароль из примера предназначен исключительно для локальной тестовой базы.
Порт опубликован только на 127.0.0.1. Перед запуском на сервере нужна отдельная
конфигурация инфраструктуры, а не копирование локального примера.

Без базы можно проверить SQL: `uv run alembic upgrade head --sql`.
Локально эта проверка прошла; реальное применение, откат и повторное применение
пока не проверены. Workflow подготовлен, но не запускался в GitHub.
