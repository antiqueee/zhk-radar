# Мегаполис Интеледженс

Внутренний инструмент агентства: найти проблемные ЖК, открыть PDF-разбор,
при необходимости добавить переписку и уточнить предложение услуг.

**Реализован рабочий MVP с интерфейсом, расписанием и серверным режимом.
Реальные подключения и размещение на сервере требуют эксплуатационной проверки.** Все исходные требования сохранены в [SPEC](docs/SPEC.md).

```sh
uv sync --frozen
uv run radar serve
```

Открыть **http://127.0.0.1:8765** или запустить `Запустить Мегаполис.command`.
Ключи добавляются через «Подключения» в шапке. Модели ролей настроены по умолчанию; необязательная замена — выбор из каталога OpenRouter без ввода ID. Без ключей доступны материалы
агентства, импорт Excel/JSON, уточнения и PDF; отдельные демо-примеры вымышлены.

Реализовано:

- Простой интерфейс с логотипом агентства, поиском по списку и PDF в один клик.
  Карточка открывается по всей строке; «Не берём в работу» скрывает объект,
  «Показать скрытые» позволяет вернуть его без потери материалов.
- Сохранение ключей через сайт; модель заменяется через настройки, без правок кода.
- Фоновый поиск: Yandex → чтение публикаций → модель OpenRouter → проверка цитат → карточки.
  Прогресс сохраняется, страницу можно закрыть; доступны отмена и повтор с кешем.
  Поиск и модели проверены также на реальных подключениях; результаты остаются кандидатами для проверки.
- Загрузка открытого HTML/текста с лимитами, снимки источников, даты публикаций.
  Недоступная страница не срывает поиск; её поисковый фрагмент помечается отдельно.
- Консервативное объединение публикаций по названию ЖК, региону и корпусу;
  хронология, источники и темы попадают в карточку и PDF.
- «Попробовать без ключей» запускает весь конвейер на вымышленных источниках без сети.
- Импорт пяти форматов Excel с происхождением каждой строки: локально 102 записи,
  из них 64 записи по объектам/смешанным сущностям в главном списке, включая повторы.
- SQLite для локальных решений, истории, доказательств и версий PDF.
- PDF ровно на две страницы: ситуация, цитаты и чаты → до трёх адаптированных услуг, действия и замер.
  Логотип, схема и кликабельные источники; полные материалы остаются в карточке.
- Методическая база Мегаполиса: изучен 31 документ, составлено 15 методов с условиями,
  механиками и вариантами ресурсов. Отчёт и чат получают до 6 подходящих методов;
  модель адаптирует их к источникам ЖК. Дословное копирование шагов вызывает один запрос
  исправления; архивные КП не становятся фактами о новом объекте. Подробнее: [разбор файлов](docs/AGENCY_KNOWLEDGE.md).
- Telegram: вход по номеру/коду/2FA, чтение открытых чатов по ссылке, инкрементальный сбор,
  HMAC авторов и сводки. Отдельная модельная разметка с проверкой дословных цитат.
- Недельное расписание по Москве, опциональное чтение чатов и доставка дайджеста ботом;
  история запусков и защита от повторной отправки при неопределённом ответе.
- Общие лимиты количества платных вызовов на операцию/сутки/месяц, учёт попыток и кэш.
- Сравнение Yandex, Perplexity Search и Brave на одинаковых запросах; оценки аналитика.
  Две выбранные модели получают одинаковые фрагменты, результаты не попадают в реестр.
- Стоп-лист объекта/девелопера, причины отказов, защита от предложения существующим клиентам.
- Реестровые снимки ЕИСЖС, явная привязка корпуса, история сроков и расчёт R1–R7 по доступным
  данным. Импорт снимка при недоступности реестра; отдельный публичный сборщик портфелей ЕРЗ.
- Независимое модельное ревью и решение аналитика, привязанные к версии отчёта.
- Google Sheets: 8 вкладок, идемпотентная синхронизация, отдельные заметки и импорт стоп-листа.
- Серверный вход с ролями, отзыв сессий при смене пароля, журнал действий, HTTPS Compose.
- Ежедневные проверяемые резервные копии SQLite и офлайн-тесты; браузерные сценарии.
- Двухэтапное исследование: до 10 ЖК × 2 запроса, затем до 3 ЖК × 4 новых запроса.
  Повторные запросы используют кэш; модельный текст ограничен 32/64 тысячами знаков.
  Карточки показывают число публикаций и сайтов; перепечатки не считаются независимыми фактами.
- Модельный автор → независимая проверка → одна доработка, библиотека утверждённых кейсов.
- Отдельный клиентский PDF с проверкой версии и одобрением аналитика.
- Автоскрининг открытых чатов после интернет-поиска: Telegram API читает до 1500 сообщений
  за 30 дней; ограниченная модельная разметка включается отдельно от сбора.
- Ночное чтение/разметка и сравнение недельной динамики.
- Денежные резервы, опциональные уведомления, SMTP-дайджест и зашифрованная копия в AWS S3.
- Адаптеры hh/VK и ограниченный поиск по ИНН на открытых страницах ЕФРСБ.
- Измерение precision/recall на вручную проверенной выборке; демо не выбирает победителя.
- Начальная схема PostgreSQL/Alembic остаётся отдельным прототипом; рабочий веб-MVP — SQLite.

Расписание требует постоянно работающего приложения. API поиска, моделей и Telegram проверены на живых подключениях и с подменами; Sheets — с подменами. ЕРЗ проверен на публичных страницах, регион подтверждается ключом в ссылках строк. ЕИСЖС возвращала
403: адаптер не обходит защиту, импорт явно маркируется. Docker отсутствует в среде разработки,
поэтому контейнерный запуск и TLS ещё не проверены на целевом сервере.

Прямой контрактный API ЕФРСБ, отдельный клиентский портал и миграция
в PostgreSQL остаются расширениями исходного ТЗ. VK/hh, SMTP и S3 реализованы на подменах;
для них остаётся проверка реальных подключений. Качество найденных объектов и адаптаций услуг
нужно оценить с агентством на реальных данных. Учебные сценарии не заменяют такую проверку.

PDF проверен на всех 102 исходных записях и учебном досье с хронологией.
Загрузчик дополнительно проверен на двух ссылках РБК из таблиц: одна статья прочитана,
второй ответ отмечен как неподдерживаемый. 12 ноября выполнены живые поисковые прогоны и чтение открытого чата Telegram; это не подтверждение полноты охвата или достоверности каждого сообщения.
PostgreSQL локально не установлен: миграция проверялась генерацией SQL,
GitHub workflow подготовлен, но не запускался. Материалы, ключи и рабочие данные
не включены в Git. Шрифт DejaVu поставляется с лицензией, логотип предоставлен заказчиком.

В «Подключения → Вход в Telegram» доступен вход по QR: на телефоне откройте Telegram → Настройки → Устройства → Подключить устройство. QR автоматически обновляется до 5 минут; при включённой двухэтапной проверке введите пароль на сайте. Сессия сохраняется локально в `.env`. Вход по номеру доступен как дополнительный способ.

Текущий сценарий: выбрать регион (Россия — 16 регионов), при желании указать ЖК/девелопера и запустить поиск. Внутри: ЕРЗ/исходные материалы → поисковые страницы → до пяти подробных исследований и открытых чатов → карточки. Портфельный перенос не переносится на каждый дом. Подробности охвата и пропусков видны в результате; недоступный чат не считается прочитанным. Кнопка PDF запускает автора при настроенном API, сохраняет версию и скачивает двухстраничный внутренний разбор.

### Диалог по ЖК и стратегическое предложение

В карточке ЖК появился сохраняемый диалог с аналитиком. По умолчанию он использует материалы объекта и последние шесть завершённых вопросов. Опция «Дополнительно поискать в интернете» выполняет до двух поисковых запросов; действуют общий бюджет и кэш. В ответе фактические блоки имеют ссылки на сохранённые источники, предложения отделены от фактов. Контекст ограничен 30 источниками, его размер виден под ответом. Проверка ссылок не заменяет содержательную проверку выводов аналитиком.

После прогона кнопка «Расширить поиск» запускает следующие направления: форумы и коллективные обращения, затем реестры и проверки. Это до двух дополнительных проходов, а не неограниченный сбор. Исторические материалы в этих проходах ищутся без ограничения дат; актуальность проверяется отдельно. Адресное исследование ЖК теперь включает шесть запросов, в том числе причины и историю переносов.

PDF остаётся двухстраничным: ситуация, хронология, объяснения источников, позиция компании и свидетельства покупателей — на первой; программы разрешения конфликта и конкретные действия — на второй. Отсутствие чатов больше не навязывает продажу диагностики. Методические основания и ограничения международной адаптации: [CONFLICT_PRACTICES.md](docs/CONFLICT_PRACTICES.md). Для обновления уже сохранённого отчёта нужно заново подготовить предложение из карточки; старые версии сохраняются.
