# Поиск по российским ЖК: выбор для MVP

Проверено 10 ноября 2026 года. Это архитектурная оценка по документации сервисов,
а не результат сравнительного запуска. Ключей нет; одинаковые запросы к API
провайдеров не выполнялись. Рекомендации моделей из исходного ТЗ не приняты как эталон.

## Практическое решение

Первый кандидат — Yandex Search API для поиска публикаций. Второй кандидат для
проверки пропусков — Perplexity Search API; альтернативный эксперимент — Gemini
с Google Search Grounding. Анализ найденного отделён от поисковика: один и тот же
набор источников можно передать разным моделям. Модель в проекте не выбрана по умолчанию.

Преимущество такого разделения для этого проекта: можно измерить, какой поисковик
нашёл первоисточник, а какая модель правильно определила объект и извлекла цитату.
Красивый ответ со ссылками сам по себе не показывает полноту поиска.

## Что подтверждено документацией

| Сервис | Возможности | Какую роль предлагаю проверить |
| --- | --- | --- |
| Yandex Search API | Российский тип поиска, региональное ранжирование, временной период, выдача XML/HTML | Основной поиск по русскоязычным публикациям. Это рабочая гипотеза о соответствии задаче, не доказанное превосходство в полноте |
| Perplexity Search API | Отдельная выдача JSON без генерации ответа; язык, страна, даты, домены; заголовки, URL и фрагменты | Независимый дополнительный поиск, измеряем его полезный прирост к Yandex |
| Brave Search API | Собственный поисковый индекс, страна, язык, свежесть, поисковые операторы | Ещё один участник теста; заранее не исключаем из-за английского бренда |
| Tavily Search | Поиск с текстовыми фрагментами, включение содержимого страниц, страна и язык, ограничения по доменам | Проверить удобство извлечения текста и цену принятого сигнала; наличие фильтра RU не доказывает полноту RU-покрытия |
| Gemini + Google Search Grounding | Модель может обращаться к Google Search и возвращать сведения об источниках | Кандидат для дополнительного исследования объекта; оценивать вместе с инструментом поиска, отдельно от качества модели на фиксированных текстах |

Источники: [Yandex API](https://aistudio.yandex.ru/en/docs/search-api/api-ref/WebSearch/search),
[Perplexity Search](https://docs.perplexity.ai/docs/search/overview),
[Brave API](https://api-dashboard.search.brave.com/api-reference/web/search/get),
[Tavily API](https://docs.tavily.com/documentation/api-reference/endpoint/search),
[Google Grounding](https://ai.google.dev/gemini-api/docs/google-search?hl=en).

Для ручного запуска Yandex синхронный тариф днём — 488 ₽ за 1000 запросов,
для отложенной фоновой обработки — 30,5 ₽ за 1000, с НДС. Текущий поисковый пилот
делает до 12 поисковых вызовов по четырём приоритетным регионам: примерно 5,86 ₽
по дневному синхронному тарифу,
плюс отдельная стоимость выбранной модели. Это цена одного маленького прогона,
не бюджет полного мониторинга страны. [Официальный тариф Yandex](https://aistudio.yandex.ru/ru/docs/search-api/pricing).
Цены остальных сервисов следует фиксировать в момент сравнительного запуска;
универсальную оценку стоимости модели до выбора её идентификатора не приводим.

## Как получить объективный выбор

1. Из материалов агентства выбрать 30 ЖК: 10 Москва/МО, 10 Петербург/ЛО,
   10 остальные регионы. Вручную проверить даты и первичные ссылки для эталона.
   Сами исходные таблицы пока не являются подтверждённым эталоном.
2. Отдельно проверять обнаружение неизвестных ЖК широкими запросами и поиск
   подробностей уже известного ЖК. Не подставлять известное имя в тест обнаружения.
3. Дать поисковикам одинаковые запросы на русском, периоды и лимит результатов,
   запустить в один день. Нельзя сравнивать бесплатный чат одного сервиса с API другого.
4. Скрыть имя провайдера при оценке. Для каждого результата отметить релевантность,
   первоисточник, дату события, корпус, дубли и уже неактуальный конфликт.
5. Считать precision@10, покрытие проверенных событий, долю официальных источников,
   цену одного принятого сигнала и количество новых полезных ссылок сверх Yandex.
   Recall по эталонным событиям не означает полноту всего интернета.
6. На одинаковых сохранённых текстах сравнить модели: правильность ЖК/корпуса,
   даты, дословность цитат, соблюдение JSON, пропуски и выдуманные факты.
   Выбирать по цене корректного результата, а не по общему рейтингу модели.

## Ограничения поиска

Поисковый фрагмент не доказывает актуальную просрочку и не заменяет проверку полной
страницы и проектной декларации. Дата страницы не равна дате события. Один ЖК может
содержать корпуса с разными сроками. Индексируемые Telegram-страницы не заменяют
чтение истории открытого чата. Важные официальные источники должны получать
отдельные прямые сборщики, а не зависеть только от поисковой выдачи.

## Реализация сейчас

Написан и проверен на подменах Yandex → OpenRouter → Pydantic → дословная цитата →
карточка с цитатами и хронологией. Добавлен загрузчик HTML/текста, снимки источников,
фоновый запуск и консервативное объединение по ЖК/региону/корпусу. Дубликаты и
успешные шаги кешируются. Боевой вызов поиска/модели с ключами не проводился. Perplexity и Brave реализованы в сравнительном стенде. Tavily и Gemini Grounding остаются
кандидатами расширения; их нет в основном конвейере.


## Реализованный сравнительный стенд (10.11.2026)

В «Подключениях» доступен запуск одинаковых запросов для Yandex, Perplexity Search
и Brave, затем двух выбранных моделей на общем наборе фрагментов. Сохраняются выдачи,
время, признаки кэша, ручные оценки релевантности и результаты проверки имени/цитаты.
Это инструмент для будущего измерения, не завершённый бенчмарк на реальных ключах.
Время кэша не сопоставляется с временем API; полнота без эталона не рассчитывается.

Официальные контракты адаптеров:
- [Perplexity Search](https://docs.perplexity.ai/api-reference/search-post).
- [Brave Web Search](https://api-dashboard.search.brave.com/api-reference/web/search/post).
- [Telethon: авторизация](https://docs.telethon.dev/en/stable/basic/signing-in.html),
  [сессии](https://docs.telethon.dev/en/stable/concepts/sessions.html).
- [Telegram Bot API: sendMessage](https://core.telegram.org/bots/api#sendmessage).

Telegram здесь — дополнительный источник по уже найденному объекту, не замена веб-поиска.


## Измерение по эталону (11.11.2026)

В настройках добавлен импорт сверенного JSON-эталона с уникальными событиями и находками
каждого участника: precision, recall, F1, пропуски, дубли и интервал неопределённости.
Ручная оценка разметки чатов и принятых предложений хранится отдельно. Это инструмент
оценки, а не заявление о достигнутом качестве. Формат и критерии — в
[AUTONOMOUS_WORKFLOW.md](AUTONOMOUS_WORKFLOW.md#объективная-оценка).
