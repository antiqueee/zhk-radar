# Локальная версия Мегаполис Интеледженс

## Запуск и основной сценарий

`uv sync --frozen`, затем `uv run radar serve`, открыть http://127.0.0.1:8765.
Также работает `Запустить Мегаполис.command`.

1. В «Подключениях» сохранить Yandex API key / Folder ID, OpenRouter и идентификатор модели.
2. Выбрать географию и период, нажать «Найти объекты».
3. Открыть карточку, проверить источники и получить PDF.
4. При необходимости добавить открытые чаты и уточнить предложение.

Без ключей работают материалы агентства, импорт Excel и JSON, PDF, ручные уточнения,
добавление ссылок чатов и учебные сценарии. «Попробовать без ключей» и учебное сравнение
полностью вымышлены: они не ходят в интернет и не измеряют качество провайдеров.
Материалы агентства — импорт исходных файлов, не свежий интернет-мониторинг.

Поиск выполняется в фоне. Прогресс хранится в SQLite; перезагрузка страницы не мешает.
Приложение должно оставаться запущенным. Отмена останавливает конвейер между шагами,
уже сохранённые данные остаются. Прерванный поиск можно повторить: завершённые платные
шаги берутся из кэша. Новый день обновляет поисковую выдачу. Страницы сохраняются со
снимком текста; не прочитанная страница обозначается как поисковый фрагмент.

## Подробный PDF

Отчёт больше не ограничен двумя страницами. Разделы:

- Обложка с логотипом, исходная ситуация и предлагаемый подход.
- Основания, пробелы, хронология, сводка открытых обсуждений.
- Схемы «сигнал → действие → результат».
- Отдельные продукты: основание выбора, сигнал из публикации/чата/карточки,
  конкретный состав работ, результат для заказчика, ответственные и метод измерения.
- План на 30 дней и вопросы первой встречи.
- Приложение со всеми сохранёнными ссылками и цитатами, примерами обсуждений и методикой.

Подбор использует библиотеку 12 услуг, темы карточки/источников/чатов и явно обозначенные
ключевые признаки исходного описания. Это детерминированная проектная адаптация,
не дополнительная генерация моделью. Создание PDF не запускает поиск и не тратит API.
Необязательные продукты обозначены условными. Если оснований нет, остаётся диагностика;
количество продуктов искусственно не увеличивается. Целевые KPI и цена не выдумываются.

Один снимок содержания создаёт одну версию. Ссылки кликабельны, кириллица встроена,
длинное содержание переносится на следующие страницы без обрезки. Старые версии
доступны с сохранённым содержанием и актуальной вёрсткой. Отправки девелоперам нет.
Утверждения источников не считаются проверенными фактами. В карточке доступны история
версий, отдельное модельное ревью и решение аналитика. Одобрение одной версии не переходит
на следующую. Подтверждённые кейсы агентства в библиотеку пока не добавлены.

## Открытые Telegram-чаты

1. Сохранить API ID и API Hash своего приложения Telegram.
2. В «Подключения → Вход в Telegram» запросить код на рабочий номер.
3. Ввести код; если Telegram потребует — пароль двухэтапной проверки.
4. В карточке добавить ссылку вида `https://t.me/public_name`, нажать «Прочитать».
5. Нажать «Разобрать сообщения моделью», затем обновить PDF.

Используется Telethon 1.x. Ссылки-приглашения, закрытые каналы, личные аккаунты и ссылки
на отдельные сообщения не принимаются. Проверяется фактическая публичность канала /
супергруппы и неизменность Telegram ID. Приложение не вступает в чаты, не пишет от
аккаунта пользователя и не загружает вложения. Если публичную историю нельзя прочитать
без дополнительных действий, показывается ошибка доступа.

Первое чтение ограничено последними 30 днями; далее сохраняется позиция по ID сообщений.
За нажатие читается до 1000 сообщений. При большем объёме статус «есть ещё сообщения»:
повторное чтение продолжит с сохранённого места, дубли не создаются. Изменения и удаления
старых сообщений при инкрементальном чтении не синхронизируются. Удаление ссылки
прекращает будущий сбор, но не удаляет уже импортированную историю.

Сессия хранится только в `.env` с правами 0600 и не возвращается в браузер. Незавершённый
вход хранится в памяти и действителен 5 минут. «Забыть сессию» удаляет локальное подключение; удалённую
сессию можно отозвать в Telegram → Устройства. Учётные данные других проектов не используются.

Авторы в базе заменяются HMAC, телефоны, почта, @ники и номера квартир редактируются.
Это не гарантия полной анонимности свободного текста. Исходные имена авторов в API-выгрузке
не собираются. Тексты старше 180 дней очищаются при чтении сводки; цитаты модельной разметки
также очищаются, её кэш хранится не более 150 дней. Очистка также выполняется обслуживанием приложения раз в час; сохранённые версии PDF
и резервные копии не переписываются задним числом.

Модельный разбор — отдельное явное платное действие. Используется выбранная модель анализа
OpenRouter, до 120 неразмеченных сообщений и двух вызовов за нажатие. Ответ проходит Pydantic,
проверку индексов, допустимых тем и точного совпадения цитат. Проверка подтверждает опору на
текст, не правильность эмоциональной оценки. Повторно обработанные сообщения не оплачиваются.
Исходная разметка JSON не перезаписывается. Происхождение разметки показано в сводке и PDF.

## Недельный запуск, доставка и лимиты

Раздел «Подключения → Раз в неделю и лимиты запросов». По умолчанию всё выключено.
Выбрать день и час по Москве, географию, при необходимости чтение добавленных чатов и
доставку ботом. Для доставки нужны `TG_BOT_TOKEN` и `TG_GROUP_ID`; бот должен иметь доступ
к группе. Сохранение ключей само по себе ничего не отправляет.

Расписание запускает поиск за месяц, после завершения может прочитать связанные чаты.
Модельная разметка доступна отдельной кнопкой и в опциональном ночном цикле. Локальный дайджест сохраняется
в истории, даже если доставка выключена. Дайджест содержит статус, найденные объекты и
краткие ситуации. Это сообщение в рабочую группу, не коммерческое предложение застройщику.

Расписание выполняется внутри запущенного приложения: закрытие ноутбука или остановка
процесса откладывает запуск. После пропущенного срока выполняется один актуальный прогон,
не серия за все пропущенные недели. Ключ недельного запуска предотвращает повторное
создание завершённой задачи. Ошибка или неопределённость доставки не вызывает автоматическую
повторную отправку: Telegram не предоставляет ключ идемпотентности для sendMessage.
Статус «доставку нужно проверить» требует проверки группы. Автоматического повтора такого
сообщения и отдельной кнопки повторной доставки сейчас нет.

Лимиты общие для поиска, разбора сообщений и сравнения: на операцию, сутки UTC и месяц UTC.
Слот резервируется до платного вызова, поэтому ошибка/таймаут тоже учитываются. Кэш и учебный
режим не расходуют лимит. Это ограничения числа запросов, **не денежный бюджет**:
стоимость зависит от тарифа, модели и длины текста. Отдельно добавлен денежный резерв
и учёт `usage.cost` OpenRouter; см. [новые функции](AUTONOMOUS_WORKFLOW.md).
Чтение веб-страниц и Telegram не входит в счётчик платных поисковых/модельных API.

## Сравнение поиска и моделей

Сохранить ключи двух или трёх поисковиков: Yandex, Perplexity Search, Brave Search.
В «Сравнить поиск и модели» задать до четырёх одинаковых запросов. Можно подключить две
разные модели OpenRouter A/B — роли хранятся в `config/models.yaml`.

Все поисковики получают одинаковые запросы, русский язык и фильтр за последний месяц.
Семантика фильтра свежести у провайдеров может различаться. Сохраняются ссылки, тексты
выдачи, число доменов, длительность и признак кэша. Аналитик отмечает релевантность ссылок;
одна оценка одинакового URL/запроса применяется к нескольким выдачам. Доля релевантных
считается среди оценённых с указанием покрытия. Без эталонного списка полнота неизвестна.

Модели получают один и тот же корпус: до 8 уникальных фрагментов по 2000 символов,
выбранных с чередованием выдач провайдеров. Проверяются JSON, имя ЖК и точная цитата.
Показываются отклонённые объекты, совпадение цитат и время. Это не автоматическая оценка
истинности, полноты и качества коммерческого текста. Отдельный рейтинг «лучшая модель»
не выдумывается. Кэшированные времена нельзя сравнивать с реальными API-вызовами.

Сравнение не меняет рабочий реестр. Результаты и оценки сохраняются после перезагрузки.
Повтор в тот же день с теми же запросами и моделями использует сохранённые шаги.
Учебный пример даёт одинаковые вымышленные документы и не сравнивает реальные сервисы.
Методика: [SEARCH_EVALUATION.md](SEARCH_EVALUATION.md).

## Хранение и резервная копия

Рабочая база: `data/local/workspace.sqlite3`. Исходники: `data/intake/`.
Ключи, локальные данные и PDF-примеры исключены из Git. Значения секретов API не возвращает.
По умолчанию сайт доступен только локально. Серверный режим включает вход и роли;
подготовлены Docker Compose и HTTPS-прокси. Инструкция: [SERVER.md](SERVER.md).

`uv run radar backup` создаёт согласованную копию SQLite в `data/backups/` без ключей.
Оригиналы Excel и `.env` хранить отдельно. Для восстановления остановить приложение,
сохранить текущую папку `data/local`, положить копию как `workspace.sqlite3` в новую
папку `data/local`, затем запустить. Старые WAL/SHM не переносить рядом с копией.
SQLite независима от будущей PostgreSQL; автоматического переноса между базами нет.

## Стоп-лист, реестры и проверка

В карточке «Исключить из предложений» добавляет объект или точное имя девелопера в стоп-лист.
Такие объекты скрыты из основного списка; флажок «Со стоп-листом» показывает их для управления.
Новый PDF для них не создаётся, они не попадают в дайджест и плановое чтение чатов/реестров.
Старые версии остаются в истории. Статус работы и причина отказа сохраняются отдельно.

В «Реестр корпуса» укажите ID ЕИСЖС, проверьте адрес и подтвердите соответствие. Обновление
пытается получить карточку с официального адреса. При HTTP 403 отображается ошибка;
обход защиты не выполняется. Можно заполнить и загрузить JSON по образцу со ссылкой на
официальный документ. Ручной снимок всегда помечен как импорт, даже если в JSON указано обратное.
Отсутствие значения РВЭ не означает его отсутствие: без явной проверки соответствующие
правила не начисляются. Снимки старше 30 дней не дают допуск к коммерческому контакту.

Сравниваются заполненные даты ввода/передачи, готовность и РВЭ. Первый сохранённый срок —
не обязательно первоначальный ДДУ. Расчёт предварительный: реестровые данные и явно
введённый коммерческий контекст, без автоматического присвоения публикациям доказательных
классов. Ручные снимки имеют низкую степень доверия. Портфели ЕРЗ читаются отдельно
из первой страницы рейтинга; их переносы не приписываются конкретному корпусу.

В «Подключениях» можно выбрать отдельную модель проверки; она должна отличаться от модели
извлечения. Ревью сверяет сохранённый отчёт с контекстом цитат, даты, корпус и обоснование
услуг. Ответ проходит схему и проверку ссылок. Повтор завершённого разбора использует кэш.
Без первоисточников выдаётся необходимость ручного разбора без вызова API. Аналитик может
оставить решение и пояснение; учебный объект нельзя одобрить для коммерческого использования.

## Google Таблица

Сохраните ID таблицы и загрузите JSON сервисного аккаунта. Адрес аккаунта показывается после
загрузки: предоставьте ему права редактора в Google Таблице. Ключ обратно не выводится.
Кнопка синхронизации создаёт 8 вкладок с префиксом «Мегаполис · » и метками принадлежности:
реестр, неделя, девелоперы, чаты, воронка, справка, стоп-лист, заметки.

Системные вкладки пересобираются из локальных данных; значения записываются как текст,
формулы из источников не выполняются. У системных листов предупреждение о редактировании,
не жёсткий запрет. Чужие вкладки и содержимое «Заметок» не меняются. Существующий лист с
нужным названием, но без метки приложения, вызывает отказ без перезаписи.

«Стоп-лист» читается в приложение: record + ID карточки либо developer + точное название,
причины client/partner/refused/other. Ошибочные строки показываются, при ошибке ранее
импортированные исключения не удаляются. Локальные исключения не снимаются удалением строки
из Google. Учебные объекты в таблицу не экспортируются.

Расписание может дополнительно обновлять подтверждённые корпуса и синхронизировать таблицу.
Эти опции выключены по умолчанию. Завершённые этапы одного недельного запуска не повторяются;
ошибка реестра не мешает таблице и дайджесту. Ошибки видны в истории запуска.

## Проверки перед реальной эксплуатацией

- Ключи и баланс поиска/моделей, схема ответов и качество русскоязычной выдачи.
- Telegram: код/2FA, доступ к конкретным чатам, рабочая группа бота.
- Таблица: права сервисного аккаунта и первая реальная синхронизация.
- ЕИСЖС с целевого сервера: в разработке официальный адрес возвращал 403.
- Docker/HTTPS на выбранном сервере и внешнее хранение резервных копий.
- Проверка продуктов и формулировок агентством на реальных объектах.

Адаптеры поиска, моделей, Telegram, Sheets и доставки проверены на подменах. Боевые вызовы
с вашими ключами не выполнялись. ЕРЗ дополнительно разобран с живой публичной страницы.
Добавлены VK/hh, ограниченный поиск ЕФРСБ по ИНН, почта, S3 и клиентский PDF:
[описание и ограничения](AUTONOMOUS_WORKFLOW.md). Прямой контрактный API ЕФРСБ, отдельный
клиентский портал и перенос веб-хранилища на PostgreSQL не входят в реализованный веб-MVP.
