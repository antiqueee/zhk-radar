# Журнал решений

- 2026-11-10: создан независимый репозиторий zhk-radar; исходное ТЗ сохранено без изменений. Существующие проекты не меняем.
- 2026-11-10: до прохождения этапа 0 создаём только офлайн-основу и прототип расчётов. Это подготовка, а не принятие этапа 1.
- 2026-11-10: месяцы в правилах — календарные, 90/60/30 дней — буквальные дни; R6 трактуется как ближайшие 6 месяцев, требует согласования с бизнесом.
- 2026-11-10: окно — максимальная оценка среди текущих дат ввода и передачи. При наличии РВЭ дата ввода больше не триггер. Нет дат — 0 с ограничением.
- 2026-11-10: будущие события не влияют на скоринг. Медиа учитываются до 60 дней включительно; остальным признакам срок давности в ТЗ не задан.
- 2026-11-10: каждый тип признака остроты начисляется один раз; повторный перенос — максимум один бонус. Округление итоговой остроты half-up.
- 2026-11-10: независимость доказательств задаётся origin, а не только доменом. Перепечатка не даёт второе независимое подтверждение. Один B консервативно даёт низкую уверенность.
- 2026-11-10: неизвестная платёжеспособность даёт базу 0 и явное ограничение. Для базы 40 нужны active и solvent.
- 2026-11-10: при РВЭ правила строительного риска R1–R7 отключаются; просрочка передачи после РВЭ требует отдельного подтверждённого сигнала.
- 2026-11-10: R1/R4/R5/R6 не срабатывают на прошедшую дату. R3 покрывает просроченный ввод. Падение готовности не считается остановкой стройки — требует проверки источника.
- 2026-11-10: введена signal_documents для нескольких документов одного сигнала. Первичная миграция покрывает только основу реестра; остальные поля и таблицы добавляются следующими миграциями.
- 2026-11-10: ранние правила возвращают индикаторы, а не сохраняют сигналы. При подключении сборщика обязательны документ и проверенная цитата; оценка не заменяет доказательства.
- 2026-11-10: worker/bot/reader пока отсутствуют в Compose: их исполняемые модули ещё не реализованы. Запускаются только существующие компоненты.
