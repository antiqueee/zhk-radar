# Журнал решений

- 2026-11-10: получено разрешение изучить и переиспользовать существующий код; messagesummariser исследован только чтением. Сессии и реальные чаты не подключались.
- 2026-11-10: таблицы агентства импортируются в staging с исходной классификацией, ссылками и ячейками; не в signals. Разные шкалы приоритета и непроверенные пересказы не являются эталоном.
- 2026-11-10: PDF-архив — частичная реконструкция, онлайн-оригинал недоступен; не использовать реконструированные утверждения как подтверждённые факты.
- 2026-11-10: 12 пакетов офферов адаптированы по 19-слайдовой презентации и таблицам; approved=false до вычитки. Слайды подтверждают направления услуг, но не коммерческие условия и KPI.
- 2026-11-10: O1 доступен и на стадии 4 как диагностический fallback при неполных данных (расширение таблицы ТЗ). O12 только дополнительный и ранжируется после услуг, непосредственно отвечающих на боль.
- 2026-11-10: партнёрские логотипы Самолёт/КРОСТ — основание проверить отношения, не автоматически блокировать всю группу.
- 2026-11-10: закрытые чаты и персональные профили из общей презентации не расширяют согласованный объём Радара. Для него действуют ограничения SPEC.md.

- 2026-11-10: создан независимый репозиторий zhk-radar; исходное ТЗ сохранено без изменений. Существующие проекты не меняем.
- 2026-11-10: до прохождения этапа 0 создаём только офлайн-основу и прототип расчётов. Это подготовка, а не принятие этапа 1.
- 2026-11-10: месяцы в правилах — календарные, 90/60/30 дней — буквальные дни; R6 трактуется как ближайшие 6 месяцев, требует согласования с бизнесом.
- 2026-11-10: окно — максимальная оценка среди текущих дат ввода и передачи. При наличии РВЭ дата ввода больше не триггер. Нет дат — 0 с ограничением.
- 2026-11-10: будущие события не влияют на скоринг. Медиа учитываются до 60 дней включительно; остальным признакам срок давности в ТЗ не задан.
- 2026-11-10: каждый тип признака остроты начисляется один раз; повторный перенос — максимум один бонус. Округление итоговой остроты half-up.
- 2026-11-10: независимость доказательств задаётся origin, а не только доменом. Перепечатка не даёт второе независимое подтверждение. Один B консервативно даёт низкую уверенность.
- 2026-11-10: неизвестная платёжеспособность даёт базу 0 и явное ограничение. Для базы 40 нужны active и solvent.
- 2026-11-10: при РВЭ правила строительного риска R1–R7 отключаются; просрочка передачи после РВЭ требует отдельного подтверждённого сигнала.
- 2026-11-10: R1/R4/R5/R6 не срабатывают на прошедшую дату. R3 покрывает просроченный ввод. Падение готовности не считается остановкой стройки — требует проверки источника.
- 2026-11-10: введена signal_documents для нескольких документов одного сигнала. Первичная миграция покрывает только основу реестра; остальные поля и таблицы добавляются следующими миграциями.
- 2026-11-10: ранние правила возвращают индикаторы, а не сохраняют сигналы. При подключении сборщика обязательны документ и проверенная цитата; оценка не заменяет доказательства.
- 2026-11-10: worker/bot/reader пока отсутствуют в Compose: их исполняемые модули ещё не реализованы. Запускаются только существующие компоненты.

- 2026-11-10: по прямой просьбе пользователя добавлен веб-интерфейс поверх Python; пункт исходного ТЗ «без веб-интерфейса» заменён этим пожеланием.
- 2026-11-10: локальная SQLite даёт работающий MVP без установки PostgreSQL; серверная схема остаётся отдельной, автоматическая миграция данных между ними не заявляется.
- 2026-11-10: после пользовательского ревью UI упрощён до поиска, списка и PDF; подключение чатов внутри карточки, подключение сервисов в отдельном окне.
- 2026-11-10: логотип взят из предоставленного JPG; название «Мегаполис Интеледженс» без слеша, белый/графит/тёмно-синий вместо зелёного дашборда.
- 2026-11-10: ключи разрешено сохранять через сайт в локальный .env (0600), без возврата значений API; модель сохраняется в config/models.yaml.
- 2026-11-10: поисковый пилот использует Yandex XML и заменяемую модель OpenRouter; нет предпочтения модели автора исходного ТЗ, выбор оставлен пустым до сравнения.
- 2026-11-10: поисковые фрагменты создают кандидатов, не подтверждённые факты; точные цитаты и названия проверяются кодом, скоринг им не присваивается.
- 2026-11-10: PDF локальной версии строится reportlab с проверкой высоты и встроенным DejaVu; это сокращённый двухстраничный документ, не полное наполнение всех блоков ТЗ.
- 2026-11-10: чат-импорт локальный и только public, агрегаты не содержат авторов; темы/тональность из входной разметки, отрицательная тональность не трактуется как доля конфликта.
- 2026-11-10: поиск перенесён в локальный фоновый worker; HTTP возвращает 202 и ID задания, прогресс переживает перезагрузку вкладки; прерванные при остановке приложения задания не перезапускаются автоматически.
- 2026-11-10: полные HTML/текстовые страницы загружаются с проверкой и закреплением публичного IP; ошибки и неподдерживаемые форматы дают явный fallback к фрагменту поиска.
- 2026-11-10: объединение только по нормализованному названию, подтверждённому текстом региону и конкретному корпусу; неизвестные сущности не догадочно сливаются с конкретными.
- 2026-11-10: дата события принимается только при её явном присутствии в цитате, отдельно от метаданных публикации; это не автоматическая сертификация достоверности утверждения.
- 2026-11-10: публикация с той же цитатой и URL не становится новым событием из-за рекламы в HTML; сохранённые тексты отделены от хеша исходного ответа.
- 2026-11-10: весь поисковый путь доступен в явно обозначенном учебном режиме, с локальными подменами сети и модели; учебные записи отделены от рабочих.

- 2026-11-10: по повторному запросу пользователя снят двухстраничный лимит PDF; отчёт включает исходный логотип, схемы, отдельные продукты, конкретные сигналы и полный список источников. Сведения отделены от проектных действий; пустые KPI не заменяются придуманными целями.
- 2026-11-10: предложения строятся из проверяемых правил и 12 предметных сценариев; ключевые слова исходного описания дают только условные гипотезы продуктов. Модели не вызываются при создании PDF.
- 2026-11-10: Telegram-читатель использует Telethon StringSession в .env (0600), авторизацию через локальный UI и только публичные Channel/supergroup; нет вступления, отправки от аккаунта или доступа к чужим сессиям.
- 2026-11-10: чтение сообщений сохраняет курсор и Telegram ID; предел 1000 за запрос, история первого чтения 30 дней. Изменения и удаления старых сообщений пока не синхронизируются.
- 2026-11-10: модельная разметка чатов запускается отдельно, проверяет схему, тему, индекс и точную цитату; повторные сообщения не размечаются. Метрики и PDF показывают происхождение разметки.
- 2026-11-10: недельный worker включается явно, хранит UTC, планирует по Москве; пропущенные недели объединяются в один текущий запуск. Работает только при запущенном локальном приложении.
- 2026-11-10: отправка дайджеста включается отдельным флагом; неопределённый результат sendMessage хранится как uncertain и автоматически не повторяется, поскольку у Bot API нет клиентского ключа идемпотентности.
- 2026-11-10: лимиты платных вызовов резервируются транзакционно до запроса, общие для поиска/чатов/сравнения; ошибки тоже расходуют слот. Денежная стоимость неизвестна и не показывается нулём.
- 2026-11-10: сравнительный стенд использует одинаковые русские запросы для Yandex/Perplexity/Brave и общий корпус для двух моделей; ручная релевантность отделена от совпадения цитат. Без эталона нет заявления о полноте или победителе.

- 2026-11-11: Веб-MVP остаётся на SQLite WAL с одним процессом; серверный запуск добавлен через HTTPS, роли и постоянный том, без ложного объявления миграции в PostgreSQL.
- 2026-11-11: Ручной реестровый снимок имеет низкое доверие; отсутствие РВЭ не выводится из пустого поля. Привязку корпуса подтверждает оператор, просроченные снимки не дают допуск.
- 2026-11-11: Ревью и решение аналитика связаны с неизменной версией отчёта; новая версия требует нового решения. Проверка опоры на текст не равна подтверждению истинности.
- 2026-11-11: Sheets изменяет только вкладки с метками приложения; ручные заметки и стоп-лист не перезаписываются. Ошибки импорта исключений не должны снимать старые ограничения.
- 2026-11-11: Резервная копия SQLite создаётся ежедневно и проверяется до публикации; внешнее хранилище и TLS должны быть проверены на инфраструктуре заказчика.
