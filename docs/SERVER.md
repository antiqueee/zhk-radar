# Серверный запуск

Рабочий MVP использует SQLite WAL и один процесс приложения. Не запускайте несколько
воркеров/реплик на одной базе. PostgreSQL из исходного архитектурного прототипа не является
хранилищем веб-приложения; автоматической миграции между ними нет.

## Локальный компьютер

```sh
uv sync --frozen
uv run radar serve
```

Открыть http://127.0.0.1:8765. Без серверного режима внешний сетевой интерфейс запрещён CLI.
Локальный пользователь имеет права администратора. Для коллег используйте серверный режим.

## HTTPS и Docker Compose

Нужен сервер с Docker Compose, домен с DNS на этот сервер, открытые 80/443. Caddy выпускает
TLS-сертификат. Вход с паролем включён до открытия приложения наружу. Поисковые и модельные
ключи не обязательны для запуска, их можно добавить позже через сайт.

В `.env` рядом с compose-файлом укажите только домен для развёртывания:

```dotenv
RADAR_DOMAIN=radar.your-company.ru
```

Не размещайте рабочие ключи в Dockerfile, образе или compose-файле.

```sh
docker compose -f compose.server.yaml build
docker compose -f compose.server.yaml run --rm radar radar user-add admin --role admin
docker compose -f compose.server.yaml up -d
docker compose -f compose.server.yaml ps
```

Команда user-add запрашивает пароль в терминале без вывода. Минимум 12 символов.
Приложение откажется запускаться в серверном режиме без администратора и HTTPS origin.
Данные и настройки хранятся в постоянном томе `radar_workspace` (`/workspace` внутри контейнера).
Исходные конфиги копируются туда только один раз. Ключи из сайта сохраняются в `/workspace/.env`.
Для загрузки нового кода повторите build и up; том с данными сохранится. Перед обновлением
сделайте копию. Не используйте `down -v`: эта команда удаляет постоянные тома.

Дополнительные пользователи / смена пароля и роли:

```sh
docker compose -f compose.server.yaml exec radar radar user-add analyst1 --role analyst
docker compose -f compose.server.yaml exec radar radar user-add reader1 --role viewer
```

- admin: подключения, расписание, таблица, резервные копии и весь рабочий процесс;
- analyst: поиск, чаты, карточки, PDF и проверка, без доступа к настройкам ключей;
- viewer: чтение карточек и уже созданных PDF без изменения данных.

Смена пароля/роли отзывает старые сессии пользователя. Сессия действует 8 часов, cookie —
Secure/HttpOnly/SameSite=Strict, токен в базе хранится как хеш. Пароли — scrypt с отдельной солью.
Есть лимит попыток входа, проверка Origin/Host и журнал изменений без тел запросов/секретов.
`RADAR_USERS` хранится в .env; для удаления пользователя удалите только его запись из этого
JSON и сохраните файл. Пользователь не сможет продолжить старую сессию.

Для альтернативного reverse proxy задайте `RADAR_SERVER_MODE=true` и
`RADAR_PUBLIC_ORIGIN=https://...`, создайте администратора и используйте
`radar serve --host 0.0.0.0`. Приложение не должно быть доступно по HTTP в обход TLS-прокси.

## Резервные копии и восстановление

При запуске и раз в час проверяется наличие успешной копии за текущие сутки UTC.
Копия создаётся через SQLite backup API, проверяется `integrity_check` и публикуется атомарно.
Файлы имеют права 0600. Минимум 14 последних копий сохраняются; более старые удаляются только
после 14 дней. Ошибка видна в «Подключения → Резервные копии».

Ручная копия: кнопка на сайте либо `uv run radar backup` (в контейнере `radar backup`).
Копии SQLite не содержат ключей .env, конфигов и оригинальных Excel. Их нужно копировать
отдельно в защищённое внешнее хранилище. Автоматическая зашифрованная выгрузка в AWS S3 реализована, но по умолчанию выключена:
её доступы, bucket и ключ Fernet задаются в «Подключениях». В S3-архив также входят YAML-конфиги,
но не .env и оригинальные Excel. Сервис хранилища требует живой проверки. Копия на том же диске не защищает от
потери самого сервера.

Восстановление локально:

1. Остановить приложение.
2. Переименовать текущую `data/local` в архивную папку с датой, сохранив её целиком.
3. Создать новую `data/local` и скопировать проверенную резервную копию как
   `data/local/workspace.sqlite3`. Не переносить старые `-wal`/`-shm` рядом с ней.
4. Восстановить соответствующие `.env` и `config`, права 0600 для .env и базы.
5. Запустить, открыть известный объект, историю PDF и подключения.

Для контейнера те же операции выполняются в томе `/workspace` при остановленном сервисе
radar; вспомогательный контейнер запускается `docker compose ... run --rm --entrypoint sh radar`.
Сначала сохранить исходный том вне сервера. Нельзя заменять SQLite работающего процесса.

## Наблюдение и ограничения проверки

`/healthz` проверяет доступность базы; healthcheck контейнера вызывает его каждые 30 секунд.
Он не утверждает, что внешние API доступны. История поиска, недельных запусков, синхронизаций,
проверок отчётов и копий доступна в приложении. Журнал контейнера ограничен 3 файлами по 10 МБ.
Журнал доступа хранится 180 дней. Удаление старых текстов чатов выполняется при чтении сводок.

Серверный вход и роли проверены HTTP-тестами; восстановимость SQLite — чтением независимой
копии. Docker в среде разработки отсутствует: образ, TLS и запуск Compose необходимо
проверить на целевом сервере. Развёртывание на внешнем сервере не выполнялось.


## Восстановление зашифрованного архива S3

Скачайте нужный `.tar.gz.fernet` из настроенного bucket и возьмите отдельный ключ из менеджера
паролей. На тестовой машине с установленным проектом выполните, указав свои пути:

```sh
uv run python - <<'PYCODE'
from pathlib import Path
from getpass import getpass
from radar.web.external_ops import decrypt_archive
# Создаётся новый файл с правами 0600, существующий не перезаписывается.
decrypt_archive(Path("backup.tar.gz.fernet"), Path("restored.tar.gz"), getpass("Ключ Fernet: "))
PYCODE
tar -tzf restored.tar.gz
```

Проверьте состав: `workspace.sqlite3` и разрешённые `config/*.yaml`. Распаковывайте в отдельную
пустую папку; далее используйте описанную выше процедуру остановки/замены базы. Восстановите
.env из отдельного защищённого источника. Установите нужные значения расписания и доставки
до старта восстановленной копии: данные содержат сохранённые флаги автоматизации.

Офлайн-тест расшифровывает архив и проверяет отсутствие .env; полноценную учебную процедуру
с сервером и настоящим bucket нужно выполнить после подключения и повторять ежемесячно.
Нельзя считать успешный PUT проверкой всей процедуры восстановления.
